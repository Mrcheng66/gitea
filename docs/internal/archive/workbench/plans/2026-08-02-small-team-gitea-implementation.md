# 小团队 Gitea 平台实施计划

## 目标

按已确认设计交付可部署的 Gitea 单机栈、COS 日备份、健康检查、systemd 定时任务和运维文档，不引入 CI/CD、独立数据库或监控平台。

## 步骤与验证

1. 基础服务配置
   - 创建固定版本的 `compose.yaml`、`.env.example` 和宿主机 Nginx 路由示例。
   - 验证：`docker compose config` 成功，配置中无 `latest` 镜像，Gitea Web 只绑定宿主机回环地址。
2. Gitea 初始化
   - 通过环境变量关闭注册和范围外功能，提供一次性管理员创建脚本。
   - 验证：配置键与 Gitea 1.27.1 官方示例一致，脚本语法检查通过。
3. COS 备份
   - 提供 COSCLI 安装、私密配置生成、备份上传、远端校验和状态记录脚本。
   - 验证：本地替身测试覆盖成功路径、上传失败、Gitea 必须重启和当前备份不得被失败任务替换。
4. 状态检查与日志
   - 检查 HTTPS、证书、磁盘和最近一次成功备份，失败时返回非零状态并写入 systemd journal。
   - 验证：本地替身测试覆盖健康状态和备份过期状态。
5. 定时与运维
   - 提供备份、健康检查的 systemd service/timer，以及部署、升级和恢复文档。
   - 验证：单元文件通过 `systemd-analyze verify`（Linux 环境）或静态字段检查。
6. 总体验收
   - 运行 Shell 语法、Compose 渲染、敏感信息和版本固定检查。
   - 对照设计文档的九项验收标准记录需要在真实服务器完成的检查。
