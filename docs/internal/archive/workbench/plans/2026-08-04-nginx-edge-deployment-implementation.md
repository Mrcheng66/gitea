# Nginx 边缘代理部署实施计划

## 目标

将项目从内置边缘代理部署改为宿主机现有 Nginx 部署。Compose 仅管理 Gitea 与 Workbench；配置、脚本、测试和运维文档保持一致。

## 步骤与验证

1. 调整容器入口
   - 删除 Compose 中的内置边缘代理服务及相关环境变量。
   - 将 Gitea 3000 和 Workbench 8081 绑定到 `127.0.0.1`。
   - 验证：Compose 渲染成功，两个 Web 端口均不绑定公网，SSH 2222 保持不变。
2. 提供 Nginx 路由
   - 新增可合并到现有 HTTPS `server` 块的路径分流示例。
   - 将旧路由测试替换为 Nginx 路由测试。
   - 验证：Workbench 精确路径进入 8081，近似路径和 Gitea 路径保持在 3000。
3. 清理备份与恢复依赖
   - 备份脚本及测试不再要求或归档旧边缘代理配置。
   - 恢复与升级流程只管理 Gitea 和 Workbench。
   - 验证：备份成功和失败恢复测试全部通过，归档仍包含两个数据目录和私密配置。
4. 统一文档
   - 更新 README、部署、升级、恢复、验收、设计说明和既有实施计划。
   - 明确 Nginx/证书由宿主机管理，并给出安全上线及回退步骤。
   - 验证：运行依赖、命令和架构描述不存在旧方案残留。
5. 完整验证
   - 运行 `tests/check.sh`。
   - 运行 `go test ./...`。
   - 运行前端测试、类型检查和生产构建。
   - 运行 `git diff --check` 并人工审阅最终差异。
