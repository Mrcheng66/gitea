# 研发项目工作台卡片紧凑布局设计

日期：2026-08-10

状态：已确认，待书面审阅

范围：登录首页研发项目工作台中的项目执行卡片

## 1. 问题

当前项目卡片将负责人、参与人和真实研发进展分别放在项目决策区之后。即使这些信息较少，也会占据多个完整横行；与此同时，项目标题与目标日期之间存在较大空白，导致卡片纵向空间利用率偏低。

本次调整只重新组织卡片内已有信息，不改变数据来源、权限、链接、展开状态或项目排序。

## 2. 目标

- 利用项目标题与目标日期之间的空白展示相关人。
- 负责人和参与人不再单独占据一整行。
- 在项目进度下方，用一行同时展示真实研发进度结论和最近一条研发记录。
- 保留当前问题与下一步行动的并列结构。
- 不减少现有信息和交互能力，并兼顾窄屏阅读。

## 3. 已评估方案

### 3.1 直接上移

把现有相关人区域和真实研发进展区域原样移到决策区之前。改动最小，但卡片仍由多个完整横行组成，压缩效果有限。

### 3.2 相关人横向合并到项目头部

把负责人和参与人作为一条横向信息放在标题区域。桌面端可利用空白，但中等宽度容易换成独立一行，不能稳定满足紧凑目标。

### 3.3 相关人纵向放在目标日期左侧

将相关人组织成两行小信息块：负责人一行、参与人一行。该信息块固定处于目标日期左侧，项目标题和描述仍在左侧主区域。这是确认采用的方案。

## 4. 确认布局

### 4.1 项目头部

桌面端头部使用三列：

1. 项目标识、阶段、项目名称和描述，占据剩余宽度。
2. 项目相关人，位于目标日期左侧。
3. 目标日期，保持右对齐。

项目相关人采用纵向两行：

- 第一行展示“负责人”、负责人头像和姓名；未设置负责人时展示现有未指定状态。
- 第二行展示“参与”、参与人头像列表；没有参与人时展示现有空状态。
- 多名参与人的头像继续使用紧凑叠放方式，并保留人员链接和姓名提示。

### 4.2 项目进度

项目进度条、百分比及发布、合并和待处理数量继续位于项目头部下方，不改变计算方式。

### 4.3 研发进展行

在项目进度下方新增一条紧凑的横向信息带，按以下顺序展示：

1. “真实研发进度”标签。
2. 最近研发状态或空状态结论。
3. 分隔线。
4. “最近记录”标签。
5. 最近一条有效研发记录的标题、仓库和时间等现有元数据。

默认只展示最近一条记录。存在更多记录时保留现有展开与收起能力；展开后的附加记录显示在该信息带下方。活动读取失败或没有有效记录时，在同一位置显示现有错误或空状态文案。

### 4.4 当前问题与下一步行动

该区域继续使用左右两列，不改变内容、执行人和期限展示。由于相关人和研发进展已经上移，决策区成为卡片最后一个主要区块。

## 5. 响应式规则

- 桌面端保持头部三列和研发进展单行结构。
- 中等宽度优先压缩项目标题列，相关人仍保持在目标日期左侧，不生成独立整行。
- 窄屏下允许头部变为两列：项目标题在左、目标日期在右，相关人位于标题下方但仍只占左列。
- 窄屏下研发进展行可以换行，但标签、状态和最近记录的阅读顺序保持不变。
- 当前问题与下一步行动沿用现有窄屏纵向排列。

## 6. 实现边界

- 调整 `ProjectWorkbench.vue` 的卡片模板结构。
- 调整 `org-project.css` 中项目卡片相关样式和响应式规则。
- 复用现有项目人员与研发活动数据，不新增后端字段或接口。
- 不修改工作台侧栏、关注摘要、筛选范围或项目详情页。

## 7. 验证

- 为组件结构和信息展示补充或更新前端测试。
- 运行相关单文件前端测试。
- 运行 `make lint-js` 和相关 CSS 检查。
- 在桌面、中等宽度和窄屏下确认相关人位置、研发进展行、文本截断及展开状态。

## 8. 验收标准

- 桌面端负责人和参与人位于目标日期左侧，并以纵向两行展示。
- 负责人和参与人不再单独占据卡片完整横行。
- 真实研发进度和最近一条研发记录位于项目进度下方的同一行。
- 最近记录为空、读取失败或存在多条记录时均有明确且可用的展示。
- 原有人员链接、项目链接和展开收起交互保持可用。
- 卡片比调整前明显减少纵向留白，且不牺牲窄屏可读性。
